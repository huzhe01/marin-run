先说清楚这页在讲什么。「工业级 LLM 训练」在多数人的印象里是一句「拿很多数据训一个很大的模型」。 真做起来，那句话对应的是一整套彼此咬合的子系统，其中只有一个是「训练」。 下面这张图是全景；后面每一站单独展开。

01

数据：一条 13 段的流水线

experiments/datakit/
入25.6T · 292 来源 → 去重去污染−2.494T → 出23.106T · 40 簇 × 5 质量档

大多数人以为数据处理就是「过滤一下」。实际的 DAG 有 13 个阶段，而且它们的并行性质不同—— 这是整条流水线最难的地方，也是下面这张图要说的事。

  1. 01normalize原始格式 → 统一文本 schema
  2. 02embed用 Harrier-0.6B 给每篇文档做向量
  3. 03tokenize分词（供后续指纹用）
  4. 04minhash算 MinHash 签名
  5. 05global_exact_dedup全局精确去重，为每个 ID 选一条正本
  6. 06dedupLSH 找模糊重复候选簇
  7. 07verify_fuzzy_dups回原文逐对验证，只有全文匹配才标重复
  8. 08cluster/train_centroidsK-means 5000 簇 → 层次聚合到 40 个语义桶
  9. 09cluster_assign把每篇文档归到某个语义桶
  10. 10quality质量分类器打分（GLM 5.2 标注蒸馏而来）
  11. 11bloom为评测集建 n-gram Bloom filter
  12. 12decontam逐源标记与评测集重合的文档
  13. 13store属性 join + 按 (簇, 质量档) 切成 Levanter 缓存

底色标出的是全局阶段：它们必须同时看到所有来源才能算，无法按源切开并行。 其余阶段是逐源的，可以无限横向扩展。两者交替出现，正是流水线工程量的来源。

值得注意

去污染这一步在学术复现里几乎总被跳过，但它决定了你的 benchmark 分数有多少是真的。 Marin 这次针对 lm-evaluation-harness 和 Artificial Analysis Intelligence Index 做 n-gram 匹配， 删掉了约 25 万篇文档。模糊去重那一步也做得比常见实现严格：LSH 只用来找候选， 真正标记重复必须回到原文做全文匹配，还要求行数比 ≥ 0.8。

02

配方：先训 258 个小模型

Delphi · isoflop 扫描

这一站是外行最容易忽略、内行最不敢省的一步。在花 100 天训一个 535B 之前， 他们先用约 1% 的算力训了一整梯子的小模型，跨度从 3e18 到 1e23 FLOPs， 用它们拟合缩放律，再外推出大模型该用什么形状、什么学习率、什么 D/N 配比。

这不只是为了选超参。他们自己列的四条理由里，最有说服力的是后两条：

理由实际发生过的事
抓 bug如果外推出的性能明显低于历史配方，说明架构或数据有问题，还没烧钱就能发现
看训练动力学上一次梯子发现梯度范数随 token 预算涨到 4 以上，才定位到需要 logit z-loss；否则在大 batch 下会中途炸掉
全程有参照线100 天里任何一刻都知道自己相对预测线偏了多少，偏了就立刻查
区分正常与异常大跑里看到梯度范数前 40% 一路涨，因为小跑里也这样，就知道不用干预

代价是 1% 的算力。收益是把「训到一半发现配方错了」这个 100 天量级的风险， 换成一个几天就能发现的问题。258 个 isoflop 检查点全部公开在 HuggingFace 上， 外加 88 个 Delphi 检查点。

03

预训练：正在跑的那 100 天

lib/levanter · experiments/grug
模型535.5B 总 / 22.8B 激活 · 批11,264 序列 = 46.1M tokens/步 · MFU23.2% · 吞吐2.72M tok/s · 路由丢弃0.012%

模型是全 MoE：48 层，每层都是 384 个专家里 top-8 路由，外加 2 个共享专家， 隐藏维 6144、专家宽度 3072、序列长 4096。参数量 535.5B，但每个 token 只激活 22.8B。

三个非主流选择

分位均衡路由，不用辅助损失。路由器在有偏 logits 上取 top-(K+1)，第 K+1 个当作该 token 的阈值； 每个专家的偏置取自一个 10,000 桶的全局直方图分位数，下一步才以 stop-gradient 的方式施加。 这样均衡专家负载完全不碰梯度——省掉了大家习以为常的 aux loss。

combine 权重用 sigmoid 不用 softmax，重新缩放到固定和 2.5。 LatentMoE：token 先压到 3072 维隐空间，中间过一个可学习的 RMSNorm，再进专家。

自己手写 all-to-all。他们在 issue 里直说：在 JAX/XLA on GPU 上没找到更快的 MoE 通信方案， 所以自己写。注意力也是自己写的 FlashAttention-4 CuTe kernel。

把代价量出来，再把它消掉

开跑用的是 fixed_pooled_wave_all_to_all：每个发送端对每个目的地一个固定池，分三个静态 wave， 专家 ID 直接塞进激活载荷，因此不需要额外的元数据集合通信。代价是固定容量——超出的 token 直接丢掉， 整体丢弃率 3.3%（发送端 3.26%，接收端 0.047%，瓶颈在发送侧）。

他们没有含糊过去，而是同时跑两套评测：正常路由的，和关掉丢弃的。差值就是丢弃的真实标价：

评测（step 45,837）有丢弃 bpb无丢弃 bpb代价
整体0.73680.6614+0.075
ao3_english0.93570.8097+0.126
dolma_100_programing_languages0.45270.3582+0.094

分域差异接近四倍。这张表的作用不是自我批评，是给一个工程决策定价—— 它回答了「值不值得为了消除丢弃去换一套通信实现」。

2026-09-09 更新

答案是值得，而且他们做了。主跑在 step 81,716 切换到 ragged_all_to_all： 丢弃率 3.3% → 0.012%，同时 MFU 从 21.5% 升到 23.2%、峰值显存从 136.3 GiB 降到 103.6 GiB。 上面那张代价表因此整体作废——他们现在既拿到了无丢弃的质量，又跑得更快。 切换过程见第 08 站。

有一个文件把全链路串成了一张图：experiments/post_training/iceball_micro.py。 它的 docstring 第一句是「一张 Marin 图，从随机初始化预训练一路走到评测」—— 从零训 Qwen3-0.6B → 短 chat SFT → 在 GSM8K 上跑 GRPO → 把最终策略服务化 → 跑 Evalchemy 和 Harbor。 一个入口，可以按 stage 单独执行：

python -m experiments.post_training.iceball_micro --version 2026.08.01 --stage rl --run

值得注意

注意那个 62 对 8 的提交数差异。预训练和后训练在这个项目里不是一回事： 预训练是 TPU/JAX/Levanter，RL 那条链是 GPU/vLLM/PyTorch，通过钉死 commit 的外部依赖接进来。 这是行业普遍现实——两段用的是两套完全不同的技术栈，中间靠 checkpoint 格式转换和服务化接口连接。

05

评测：三条路径，各管一段

docs/explanations/evaluation.md
路径时机测什么怎么跑
在环评测训练中，每 1000 步 Paloma 16 个分片 + uncheatable_eval 的 bpb / loss Levanter 内建的 lm-eval-harness 集成，直接写 W&B
离线评测checkpoint 产出后 选择题 + 生成任务 把模型起成 OpenAI 兼容端点，Evalchemy 打它——选择题走 logprob API，和生成走同一条路
Harborcheckpoint 产出后 容器化的 agent 基准 独立的 driver，跑真实环境里的任务

把评测后端和推理后端用一个 URL 解耦，是个值得抄的工程决定： remote_inference 只管起停和存活探测，run_evalchemy 只管任务和结果契约。 换推理引擎不影响评测代码，换评测不影响服务。

更值得注意的是评测的产出形态。分数只是最浅的一层，他们还把结果做成三个公开的诊断页： 逐语料的 bpb 差值仪表盘、下钻到逐字符的电路覆盖分析、以及一个缩放律浏览器。 上面全景图里那条虚线回流，指的就是这个。

以及最直接的一个用途：知道自己现在站在哪。下一站。

三件事要分清。0.7406 是预测不是成绩——它来自预注册的缩放律，16 个子集各自校准， 用了 77 次梯级评测，最低 R² 0.971；报告里明确写着「预测假设原始 4K 配方，实际跑可能改变」。 0.8188 才是当下，那时只训了 12% 的预算，排在 OLMo 3 32B 之后完全符合预期。 而预测落点大致平齐 DeepSeek V4 Flash：能压过 Nemotron 3 Ultra-550B 和 Mistral Large 3 675B， 但离 Kimi K2 还差 8.8%。

值得注意

负责这项对比的人在结题时写道：最令人兴奋的是预测落在 DeepSeek V4 Flash 的困惑度水平， 然后补了一句——「我承认自己有点将信将疑，不过那可能是我自己的不安全感」。 把这句留在公开 issue 里，和把 0.8868 那个难看的当期数字留在表里，是同一种做法。

调度器比训练框架还大。而且过去 90 天的改动热度里，lib/iris 以 4,374 次文件改动排第一， 是第三名 Levanter（1,133）的近四倍。

执行模型：懒惰产物

所有东西——分词、训练、评测——都是一个 ArtifactStep[T] 句柄，由 name@version 唯一标识。 构造句柄不执行任何计算；把图交给 runner 才执行，而且每步只跑一次，之后永久缓存。 版本是日历版本 YYYY.MM.DD，不是内容哈希——所以路径可读、可预测。 改了构建方式但没改版本号，会给一个漂移警告并继续用缓存。

这个设计的意义在于：一个实验脚本就是一张可复现的溯源图。 你拿到别人的实验，改一个节点，其余全部命中缓存。

七条记录里，没有一条是关于模型质量的。全是内存、网络、检查点序列化和重试策略。 这就是 100 天量级训练的真实构成：模型是被设计出来的，但能不能训完，取决于你的基础设施能不能在 704 张卡上连续正确运行三个月。这也解释了为什么调度器的代码量比训练框架还大。

更硬的线索来自同日的另一次故障：机架 9 报 CUDA_ERROR_NVLINK_UNCORRECTABLE—— 硬件级的 NVLink 不可纠正错误。负责人指出机架 9 这一周每次调度都落在同一批物理节点上， 且此前已被标记为 barrier 落后者。也就是说，他们现在怀疑这不是自己的 bug， 而是云厂商的机架有问题——而作为租户，他们看不到 fabric-manager 的日志。

10

让这套流程与众不同的，是那个环

docs/explanations/experiments.md

所以，一次工业级 LLM 训练到底是什么样子？把这十站合起来看，答案大致是：

一份数据流水线（13 个阶段，三处全局同步点，损耗 10%）、 一次 1% 算力的预演（258 个小模型换一条外推线）、 一个三个月不能停的训练作业（704 张卡，23% MFU，开跑头两周约 5% 时间花在故障恢复上）、 两套互不兼容的技术栈（预训练 JAX/TPU，RL PyTorch/GPU）、 三条评测路径（在环、离线、agent）， 以及一个比训练框架还大的调度器。

模型架构上的巧思——分位均衡、LatentMoE、手写 all-to-all——当然重要， 但它们在总工作量里的占比，远小于任何一篇论文会让你以为的比例。 最能说明问题的是这页更新时改动最大的两节：第 03 站的丢弃代价表整体作废， 第 08 站多出一整段换代实录——三周里最重要的进展，是一次通信实现的替换。
